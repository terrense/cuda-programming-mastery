# 项目维护指南

## 分支策略

### 主要分支
- `main`: 稳定的生产版本
- `develop`: 开发分支，用于集成新功能
- `feature/*`: 功能分支，用于开发新功能
- `hotfix/*`: 热修复分支，用于紧急修复

### 工作流程
1. 从 `develop` 创建 `feature/` 分支
2. 开发完成后合并回 `develop`
3. 定期从 `develop` 合并到 `main`
4. 紧急修复直接在 `hotfix/` 分支进行

## 版本管理

### 语义化版本
- `MAJOR.MINOR.PATCH` (例如: 1.2.3)
- MAJOR: 不兼容的API更改
- MINOR: 向后兼容的功能添加
- PATCH: 向后兼容的错误修复

### 发布流程
1. 更新版本号
2. 更新 CHANGELOG.md
3. 创建 Git tag
4. 发布 GitHub Release
